# Package Workflow

BlueNote core is a library package. Consumers should depend on the published package, a pinned immutable Git commit/tag that includes built output, or a local checkout that has been built for active development.

## Local development

```bash
npm install
npm run check
```

`npm run check` is the required pre-PR gate. It typechecks, builds, verifies the built package can be imported by the supported Node runtime, and runs tests.

## Local consumer testing

Until the package is published, sibling BlueNote app/client repositories normally consume a pinned Git commit dependency:

```json
{
  "dependencies": {
    "@lordierclaw/bluenote-core": "git+https://github.com/LordierClaw/bluenote-core.git#<pinned-commit-sha>"
  }
}
```

For active local core development, a sibling BlueNote client can temporarily consume a local checkout with a `file:` dependency:

```json
{
  "dependencies": {
    "@lordierclaw/bluenote-core": "file:../bluenote-core"
  }
}
```

Build the core package before testing the consumer:

```bash
cd ../bluenote-core
npm install
npm run build
```

Then reinstall or refresh dependencies in the consumer repository according to that repository's package manager.

## Package contents

`dist/` is generated by `npm run build` and included in npm packages through the package `files` allowlist. Pinned Git dependency commits/tags used by sibling packages must also include current built output. Do not import private `dist/*` paths from consumers. Use the package root for general core APIs, or documented public subpaths such as `@lordierclaw/bluenote-core/search/contains-match` and `@lordierclaw/bluenote-core/api/daemon-contract` for lightweight helpers/contracts.

Before publishing or handing a package artifact to a consumer, verify the package manifest and packed contents:

```bash
npm run check
npm pack --dry-run
```
