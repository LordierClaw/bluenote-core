# Package Workflow

BlueNote core is a library package. Consumers should depend on the published package or a local checkout that has been built.

## Local development

```bash
npm install
npm run check
```

`npm run check` is the required pre-PR gate. It typechecks, builds, verifies the built package can be imported by the supported Node runtime, and runs tests.

## Local consumer testing

Until the package is published, a sibling BlueNote client can consume a local checkout with a `file:` dependency:

```json
{
  "dependencies": {
    "@lordierclaw/bluenote-core": "file:../bluenote-core"
  }
}
```

Build the core package before testing the consumer:

```bash
cd ../bluenote-core
npm install
npm run build
```

Then reinstall or refresh dependencies in the consumer repository according to that repository's package manager.

## Package contents

`dist/` is generated by `npm run build` and is included in npm packages through the package `files` allowlist. Do not import private `dist/*` paths from consumers; use only the package root.

Before publishing or handing a package artifact to a consumer, verify the package manifest and packed contents:

```bash
npm run check
npm pack --dry-run
```
